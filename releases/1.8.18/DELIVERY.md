## Completed work

Continued the user-authorized post-1.8.17 stabilization plan, preserving interrupted edits. Successful current-page lookup now says **Find again**; only an unsuccessful result for that page says **Retry this page**. An unrelated previous pasted batch no longer changes the page-action label. Secondary popup text is larger and darker, with screenshot actions still anchored. Single-current-scan history drops a repeated heading; All cases/multiple scans retain grouping and accessible names. Current docs correctly describe shipped Source Images and Reference; historical composer ideas remain deferred.

No capture/extraction algorithm, readiness delay, storage schema, permission or cloud service was added. Existing R10, Inbox/finding deletion, manual derivatives and local-data boundaries remain.

## Update and rollback

Finish captures and close Gather windows. Keep a private backup and 1.8.17 ZIP. Replace all files in the **same installed account-id-tool directory**, then click **Reload** at edge://extensions and confirm 1.8.18. Never uninstall or clear storage to update. New installations use Developer mode → Load unpacked if organization policy permits. Keep the matching pre-update backup for rollback testing in a separate profile; Reference has a separate collection export/import.

## Remaining limits

This is a coworker-pilot RC. Managed/signed-in Windows, Windows scaling, native side-panel opening, OS Save/Print and work-app clipboard targets remain unverified. No fresh live-platform or provider submission occurred this run; prior provider evidence is labeled historical. Blocked sources can fail and dynamic captures can be explicitly partial. Local deletion does not erase prior exports/backups or browser/clipboard history. No universal reliability or legal certification claim.

Future Plans remains the consolidated backlog. Nested scrolling containers, custom export roots, bulk finding clear and a communication composer are not part of this release. Cloud startup configuration is saved separately from GitHub publication and the user's installed extension update.
