## New implementation

- `workspace-model.js`: versioned pure state transitions; explicit context IDs; project-scoped account entities; dated observations; independent review/inclusion/analyst notes; tasks; search states; reports; validation and non-destructive merge.
- `workspace-store.js`: service-worker queue serializes workspace writes and surfaces failed persistence. Search tab creation and capture use their original operation context. No automatic deletion or eviction.
- `workspace.html/css/js`: responsive full workspace and side panel. Includes project/scan creation and rename, Inbox, local scan filtering, source/note/task editors, review controls, observation history, movement between scans, action history, report export and backup import preview.
- `workspace-integration.js`: visible destination selection and explicit account-save actions in popup and full account tool. Existing quick copy remains available independently.
- `background.js`: authenticated extension-page messages, context-menu capture and menu destination updates.

Active destination is shared across the extension, including different browser windows. It is not a hidden per-tab assignment. New lookup batches capture project/scan context at lookup start, before asynchronous work. That context survives batch restoration, retries and interrupted-job recovery. Save buttons use the recorded context even after the active scan changes. Legacy batches without an origin use the active scan at save time. Dialogs retain the destination they opened with. Lookups do not automatically add results to a scan; saving a completed result remains explicit.

An account save keeps normalized/original URL, platform, exact ID string, extraction method, checked timestamp, supplied IDs, original notes and checked page-status data. It does not preserve full raw HTML or a byte-offset evidence trace. “Matches this account/page” describes extractor output and is not a claim about its operator.

Repeated saves of an identical account snapshot in the same scan are idempotent. A changed check timestamp or snapshot creates another observation. Exact platform IDs group only within one project (or Inbox). Unresolved/mismatched results do not acquire a grouped entity unless the original tool’s explicit correction flow has accepted the found ID.

Reports contain included items from the chosen scan, excluding records marked Excluded. They also include that scan’s task and search logs. Unreviewed evidence remains visibly unreviewed. Backup restores into empty storage preserve original records; restores into existing work remap imported record references into separate copies. Existing batches/settings are not overwritten. Colliding legacy batch IDs receive new IDs; conflicting settings/drafts are retained under archive keys and continue to be included in backups.

## Correctness changes in existing extraction

1. Replaced a whole-JSON regular expression for long numbers with a quote-aware numeric-token scan. The old replacement could corrupt quoted biography text that resembled a number token. Long integer IDs remain strings.
2. Removed the generic `profile_id` fallback gated only by page `og:url`. An unrelated recommended account could satisfy it. This deliberately returns unresolved results when account-bound evidence is unavailable.
3. A Facebook profile-owner object with an explicit different username/URL no longer inherits the page-level match.
4. YouTube owner URL parsing tolerates a malformed non-array field rather than spreading it blindly.

These changes are covered by deterministic synthetic fixtures. They may reduce successful extraction on some real page layouts; no live-platform coverage claim is made.

## Permissions and capacity

Existing platform host permissions are unchanged. Added `activeTab`, `sidePanel` and `contextMenus`. No `<all_urls>`, browsing-history permission or `tabs` permission was added. `activeTab` access follows an explicit toolbar/context-menu invocation and can lapse on navigation. Side-panel Save current page may ask the user to invoke the toolbar/right-click on a newly navigated domain. The minimum Chrome version rises to 116 for `sidePanel.open()`.

Workspace state is capped at 4 MiB to reserve room for legacy storage. Chrome’s local-storage quota still applies to the whole extension. Writes that exceed capacity fail with an error and do not evict research. Large-scale IndexedDB storage, collection archiving and deletion controls are later work; this build should not be positioned as an unlimited archive.

Research stays in browser-local extension storage. It is not encrypted by Gather and is not synced. Opening a search sends the query to the chosen provider, as a normal search does. Existing live account lookup contacts supported platforms and can use the browser’s signed-in session. Backup/report files contain the selected research and should be handled accordingly.

## 1.6.1 continuity follow-through

The two supplied prompt files were read in full and contain the same Scan Continuity brief. The Drive source folder was rechecked before these changes: 19 non-icon source files retained the previously inspected sizes and modification dates (latest September 30, 2026). The supplied 1.5.1 source and the previous 1.6.0 development implementation remain separate preserved copies.

`lookup-context.js` provides validated origin metadata shared by the popup, full tool, background worker and batch restoration. Backup imports remap legacy batch context IDs when project/scan IDs change during a non-destructive merge.

Undo stores the prior editable fields and a per-record edit version in the corresponding Gather activity event. It never restores a whole workspace snapshot or extraction payload. It refuses replay or a stale operation after a later edit to that record. Undo metadata remains valid across backup import; the visible Undo button covers the latest reversible edit made in the current workspace page.

Mechanical checks are deterministic comparisons, displayed in expandable item details. Different historical handles are not automatically labeled account compromise, person identity or attribution. Historical observations are preserved rather than refreshed implicitly.

Search-event labels now accept the full supported 2,000-character query length during backup validation. Collection record limits are enforced on writes as well as imports, so a supported workspace cannot grow beyond its own restore limit.

## Remaining scope limits

Source capture does not automatically trace a clicked result back to its search event or bind every browsing tab to a scan. A generic page save uses the visibly active destination at the explicit capture action. Account lookup results retain their lookup origin. No passive tab tracking or browsing history was introduced.

Field-level byte-offset provenance, a complete normalized technical-status taxonomy, collection trash/archive, keyboard shortcuts and live-platform validation remain pending. No new platform extractor was added. The purpose of this patch is reliable scan continuity, not expansion of the platform list.
