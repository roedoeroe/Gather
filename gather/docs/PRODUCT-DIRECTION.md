# Gather 1.8.6 direction

Make the everyday path short: open a page → Gather → inspect/copy or capture → see where it was saved. The popup now exposes on-page selection/copy and three capture modes and the destination without requiring a side panel. Full workspace depth is organized into Research, Captures, Case and Settings. Keep context readable and errors recoverable; avoid adding empty or overlapping controls.

Case data stays local. Source is public by the user's choice. Red deletion/history actions are available in Settings, account history and capture history, with specific scope and optional backup. Original images, exact IDs, deliberate associations, search-origin context and binary recovery remain product foundations.

1.8.6 is a fixes-only stabilization checkpoint. Keep feature work paused while concrete acceptance failures remain. The [goals audit](GOALS-AUDIT.md) reconciles the original 1.6.1 goals, subsequent requests and changed decisions against current code. Its retained goals are not shipped features or a request to implement the entire blueprint at once.

## Priorities

1. Native acceptance of 1.8.6 on permitted Chrome/Edge: toolbar sizing/invocation, on-page pointer/keyboard selection, screenshot permissions/rate, clipboard/save/print dialogs, controller focus, real browser zoom, downloads, known permitted profiles and cancellation/restoration on representative controlled pages. Automated/API-double evidence is already recorded; native and live-platform confidence cannot be inferred from it. Fix concrete failures first.
2. Local Reference Library: use the R3 steer and [implementation contract](QUICK-PARTS-DIRECTION.md). First complete generic local import/update/remove → fast search → clearly typed preview → explicit copy in Client Communication and Document Language. Use fictional packs while real exports are unavailable. Checkpoint it, then add temporary block composition, unresolved-field guards and explicit final review/copy. Case-aware suggestions consume recorded states with visible reasons; they never choose a conclusion or communication.
3. Keep older useful mechanics visible: **Save selected account results**, **carry forward selected confirmed identifiers into a new scan**, **field-level provenance and extraction diagnostics**, and **reusable analyst-owned query recipes**. Current per-row saving, manual new scans and method-level provenance are foundations, not completion of those workflows. Implement separate small checkpoints; retain historical observations and reset new coverage rather than treating old work as current. Clipboard blocks must preserve candidate versus confirmed decisions.
4. Strengthen adapters from current platform evidence and controlled fixtures; technical uncertainty stays technical. Validate dynamic full-page capture before implementing nested scrolling. Evaluate custom folder roots separately with supported permission and revoked/disconnected-access recovery.
5. Retain previewable documentation blocks/QC, sanitized archive/closure, broader saved-work search and date-aware evidence comparison as later work. Conditional tab groups/shortcuts, selected-tab capture, a one-input Gather Bar and Safari/iOS interoperability must demonstrate reduced effort before expanding the interface or permissions. See the audit for current limitations and minimal paths.
6. Defer broader workflow packs, richer annotation, encrypted resume capsules and optional AI. None is necessary for the first excellent retrieval/composition workflow. Paid distribution and collaboration are longer-term possibilities, not current release commitments.

Pack content remains separate from cases and public source. An absent real corpus does not block generic engineering, but it cannot establish a real taxonomy or approval. Search and composition run offline after import. No passive collection, cloud case storage, name-based merging, automated identity/relationship conclusions, threat scoring or email sending. X stays search-only.
