# Verification and release gates

## Completed here

**66 automated tests pass** under Node 24.19.0. The exact output is in `test-results.txt`. All extension JavaScript modules pass syntax checks.

The tests exercise the actual quick-worker/resolver modules with delayed synthetic HTTP responses, extraction, state transitions, service-worker storage logic with a controlled Chrome API double, message routing, context-menu event handling, manifest resources and DOM target references. They do not render the UI or constitute a live Chrome session.

Meaningful covered risks include:

- Exact IDs larger than JavaScript’s safe-integer range, long numbers inside quoted text, redirects, mismatches and unrelated embedded accounts.
- Synthetic matching fixtures for all five existing adapters.
- Quick direct-URL ID handling with no project, independent of the workspace.
- Original destination retained across delayed search tab creation and delayed source capture while switching scans.
- Same ID with a changed handle, immutable old observations and isolation between projects.
- Lookup-origin persistence through delayed resolution, worker recovery and backup import, including Inbox and legacy batches.
- Undo of five common edits, rejection of stale/replayed undo, and remapped undo references after import.
- Duplicate URL, historical-handle and newer-observation checks; long-query backup validation.
- Concurrent saves, failed writes, recovery after a storage error and truthful failed-search status.
- Review/inclusion rules, selected-scan report isolation, Inbox movement, tasks and action history.
- Exact backup round trip to empty storage, remapped import into nonempty storage and preservation of conflicting settings.
- Rejection of unsafe URLs, numeric IDs, invalid scopes, foreign backup keys and unauthorized message senders.

Run the suite from this package:

```sh
node --test tests/*.test.mjs
```

Or run `npm test` inside `account-id-tool`.

## Manual browser acceptance before routine use

1. **Quick lookup:** open a supported, consented profile. Invoke Gather, run on current page, copy an ID, close/reopen the popup and verify batch recovery. No project should be required. Confirm wrong-profile and login-wall failures remain clear.
2. **Research journey:** create Northbridge / October review; open and review a search; save a general link and selected excerpt; include an account from account tools; add a note and next action. Create Southridge / Intake, then return. Verify the destination, findings, search draft and pending work.
3. **Asynchronous isolation:** start a save/search under Northbridge, switch scans in another Gather window before completion, and confirm the result remains under Northbridge.
4. **History:** recheck a controlled synthetic account fixture with the same ID and a changed handle; save it and verify both observations and their dates. A supplied-ID mismatch must not create a trusted grouped account automatically.
5. **Side panel and permissions:** open the panel from the toolbar, change domains, save through the toolbar and context menu, and verify the access guidance when activeTab is no longer granted. Check the actual context-menu title and selection origin URL. Confirm no passive capture happens during unrelated browsing.
6. **Outputs and recovery:** exclude one finding; export Markdown and JSON and inspect exact IDs, review labels, dates and source URLs. Download a backup and import it into a separate test installation. Verify legacy batches and source notes survive.
7. **Appearance/accessibility:** inspect widths of 360–440 px and a desktop window. Check keyboard navigation, focus visibility, dialog cancellation, zoom, long project names and long source titles. Confirm no horizontal overflow.
8. **Upgrade:** update an existing unpacked copy in place without uninstalling it; confirm recent batches, copy preferences and running-work recovery. Repeat key flows in Edge separately.
