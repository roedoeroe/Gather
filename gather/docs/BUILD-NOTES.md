# Gather 1.8.14 engineering notes

This is a focused correction to the reported first-click failure and popup overflow. No permissions, dependency, storage schema, retention or capture-engine change. Previous release packages remain immutable.

- The current-tab resolver now follows a missing Instagram DOM result and missing session-source result with one public-profile request. This reuses the existing credential-free, normalized-URL, 12-second / 15-million-character bounded fetch used by pasted lookups. Previously the second click could switch into that path because failed input was retained. The first operation now performs it itself; it creates no extra lookup batch or temporary tab.
- After that request, reread the pinned source document. Accept later hydrated data, reject different IDs and ambiguous public data, reject navigation/security checks, honor cancellation and retain exact string IDs. No broad unbound profile_id fallback, authentication bypass or infinite retry loop.
- Current-page lookup sets its input without focusing the collapsed textarea. That focus was expanding Paste profile links and scrolling the popup. Failed current-page input retains its current-page meaning until the user edits it; explicit pasted drafts still take priority.
- Results and optional lookup tools scroll in their own pane. Case/SOC plus Select area / Full page / Visible area occupy a separate footer. Screenshot settings remain under Page options. Single-result completion restores the lookup pane's top so the primary action is not half clipped. Failed rows no longer need a duplicate uncertainty heading.
- Missing-data wording no longer claims the page is still loading. A result is only marked resolved when a profile-bound ID is available.

A live signed-out Chromium read of the user-authorized profile succeeded. A controlled missing-markup reproduction then ran the actual isolated reader and resolver against the live public response: one request, first-operation success, matching ID. This is not a signed-in or installed Edge test. No account identifiers, raw page source, cookies or real screenshots were added to public fixtures; the published live receipt contains only status/count/timing metadata.
