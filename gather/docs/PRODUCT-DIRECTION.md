# Gather 1.8.10 direction

Make the everyday path short: open a page → Gather → inspect/copy or capture → see where it was saved. The popup now exposes on-page selection/copy and three capture modes and the destination without requiring a side panel. Full workspace depth is organized into Research, Captures, Case and Settings. Keep context readable and errors recoverable; avoid adding empty or overlapping controls.

Case data stays local. Source is public by the user's choice. Red deletion/history actions are available in Settings, account history and capture history, with specific scope and optional backup. Original images, exact IDs, deliberate associations, search-origin context and binary recovery remain product foundations.

1.8.9 finishes the subsequently requested scrolling rectangle capture and manual red arrow/circle/black redaction tools, with remembered screenshot auto-copy and blue/white presentation. No automatic redaction or analysis. Keep broader feature work separate from this tested capture checkpoint. The [goals audit](GOALS-AUDIT.md) reconciles the original 1.6.1 goals, subsequent requests and changed decisions against current code. Its retained goals are not shipped features or a request to implement the entire blueprint at once.

1.8.10 removes demonstrated quick-lookup/filtering friction and protects unsaved image edits. The [whole-workflow usability audit](USABILITY-AUDIT.md) records what changed and the smallest useful next checkpoints. It adds no feature framework or default controls.

## Priorities

1. Native acceptance of 1.8.10 on permitted Chrome/Edge: toolbar sizing/invocation, on-page pointer/keyboard selection, screenshot permissions/rate, clipboard/save/print dialogs, controller focus, real browser zoom, downloads, known permitted profiles and cancellation/restoration on representative controlled pages. Automated/API-double evidence is already recorded; native and live-platform confidence cannot be inferred from it. Fix concrete failures first.
2. **Save selected account results** as a narrow checkpoint: visible frozen destination/count, explicit save, idempotent success/retry and exact strings. A lookup or Save does not confirm identity. This directly removes repeated row-by-row filing without adding a feature framework.
3. Local Reference Library: use the R3 steer and [implementation contract](QUICK-PARTS-DIRECTION.md). First complete generic local import/update/remove → fast search → clearly typed preview → explicit copy in Client Communication and Document Language. Use fictional packs while real exports are unavailable. Checkpoint it, then add temporary block composition, unresolved-field guards and explicit final review/copy. Case-aware suggestions consume recorded states with visible reasons; they never choose a conclusion or communication.
4. Keep older useful mechanics visible: **carry forward selected confirmed identifiers into a new scan**, **field-level provenance and extraction diagnostics**, and **reusable analyst-owned query recipes**. Current manual new scans and method-level provenance are foundations, not completion of those workflows. Retain historical observations and reset new coverage rather than treating old work as current. Clipboard blocks must preserve candidate versus confirmed decisions.
5. Strengthen adapters from current platform evidence and controlled fixtures; technical uncertainty stays technical. Validate dynamic full-page capture before implementing nested scrolling. Evaluate custom folder roots separately with supported permission and revoked/disconnected-access recovery.
6. Retain previewable documentation blocks/QC, sanitized archive/closure, broader saved-work search and date-aware evidence comparison as later work. Conditional tab groups/shortcuts, selected-tab capture, a one-input Gather Bar and Safari/iOS interoperability must demonstrate reduced effort before expanding the interface or permissions. See the audit for current limitations and minimal paths.
7. Defer broader workflow packs, text/highlight/advanced annotation, encrypted resume capsules and optional AI. None is necessary for the first excellent retrieval/composition workflow. Paid distribution and collaboration are longer-term possibilities, not current release commitments.

Pack content remains separate from cases and public source. An absent real corpus does not block generic engineering, but it cannot establish a real taxonomy or approval. Search and composition run offline after import. No passive collection, cloud case storage, name-based merging, automated identity/relationship conclusions, threat scoring or email sending. X stays search-only.

## 1.8.11 accepted correction — launch-only search

The user’s latest instruction supersedes automatic search logging and draft retention from earlier milestones. Search the web opens a new tab, and reverse-image search opens the chosen provider; neither creates search records or saves the entered query. Session-only project/scan assignments preserve filing. Existing legacy query text is removed without breaking saved evidence references. Deliberate case intake/plans and saved findings remain distinct. Gray placeholder examples now support persistent labels. Missing hydrated IDs trigger a bounded automatic same-document source read, with exact-account guards. Capture history now refreshes atomically. See [the release implementation note](SEARCH-AND-LOOKUP-1.8.11.md).

Retained priorities remain selected-result saving, local generic Quick Parts, confirmed-identifier scan carry-forward and provenance. User-owned query recipes must obey launch-only query privacy. Do not reintroduce automatic search history, require manual page source for normal lookup, add automatic redaction, or replace the extension with a hosted product.
