# Gather product direction

## The product

Gather is a local research companion that helps an analyst move from a page or query to a clear, attributable collection of findings and next steps. Its unit of progress is useful work retained in the correct scan. Account-ID extraction is the fastest entry point, not the limit of the product.

The Apple-inspired standard is coherence and restraint: a clear primary action, visible context, sensible defaults, familiar controls, and detail when it becomes useful. Extra capabilities earn their place by reducing a real transition in the research workflow.

## Decisions made for 1.6 / 1.6.1

| Decision | Reason | Consequence |
| --- | --- | --- |
| Keep the instant popup | The established open → Gather → copy loop is valuable on its own | No project creation gate |
| Add a shared workspace and side panel | Sustained research needs context beside the page and room for later review | One state model and responsive interface serve both |
| Use Project → Scan → saved items, with an Inbox | Research changes context; setup should not block capture | The destination is visible and captured when an action starts |
| Use explicit saving | Viewing a page or running a lookup is not a decision to include it | No passive browsing collection |
| Store immutable account observations separately from review choices | Handles and page details change | New checks can add observations without overwriting previous ones |
| Group exact IDs within a project | Platform account consistency is useful; inferred cross-case identity is not justified | No global identity graph or automatic person matching |
| Launch actual searches and keep action states | Search is part of the work, but launching is not reviewing | Prepared, opened, failed and reviewed remain distinct |
| Keep notes and next actions | Unresolved work should survive switching projects | Done and dismissed work remains visible in history |
| Separate reports from backups | A selected output is not a complete copy of research | Reports filter; backups preserve |
| Keep processing and persistence in the browser | The first release has no demonstrated need for a server | No accounts, cloud sync, analytics or AI inference service |

## Definition of done for the next release candidate

A fictional analyst can perform a quick lookup without a project; create Northbridge / October review; open and review a search; include an account and a general web source; add a note and task; switch to Southridge / Intake; return without losing context; and export only Northbridge’s selected findings. A delayed operation stays in its originally chosen scan. A renamed account retains its older observation. A backup restores without truncating IDs or overwriting existing research.

The accompanying build implements that path. Its logic and persistence checks pass. Real-browser toolbar, side-panel, appearance and live-platform acceptance are still release gates.

## Work that should come next, in order

1. Run the real browser acceptance journey in Chrome and Edge. Fix observed friction, accessibility issues and permission behavior before broadening the feature set.
2. Validate the five existing extractors against consented, non-sensitive pages. Document exact failures and per-stage acquisition/parsing/rendering timing. Synthetic fixtures are regression evidence, not a live platform success rate.
3. Improve daily use from that evidence: collection-level archive/trash, safer bulk inclusion, stronger local search, scan carry-forward, field-by-field source evidence, and output templates.
4. Evaluate search coverage templates and a proper X adapter as separate capabilities. X search launching does not mean X ID extraction exists.
5. Revisit mobile/Safari and the iOS Shortcut after its source/action sequence is available. Share extraction logic where feasible and fit interaction to the device.
6. Consider sync, collaboration, graph views or paid distribution only after recurring usefulness, upgrade recovery, correctness and store permission review are demonstrated.

Do not infer person identity, affiliation, intent or threat from page data. Analyst notes remain analyst statements. Do not claim complete search coverage, absence, verification of an operator, full page preservation, or performance gains without corresponding evidence.
