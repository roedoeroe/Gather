# Gather 1.8.4 direction

Make the everyday path short: open a page → Gather → inspect/copy or capture → see where it was saved. The popup now exposes three screenshot actions and the destination without requiring a side panel. Full workspace depth is organized into Research, Captures, Case and Settings. Keep context readable and errors recoverable; avoid adding empty or overlapping controls.

Case data stays local. Source is public by the user's choice. Red deletion/history actions remain in Settings and account history, with specific scope and optional backup. Original images, exact IDs, deliberate associations, search-origin context and binary recovery remain product foundations.

## Priorities

1. Native acceptance of 1.8.4 on permitted Chrome/Edge: toolbar sizing/invocation, screenshot permissions/rate, controller focus, real browser zoom, downloads, known permitted profiles and cancellation/restoration on representative controlled pages. Automated/API-double evidence is already recorded; native and live-platform confidence cannot be inferred from it. Fix concrete failures first.
2. Local Reference Library: use the R3 steer and [implementation contract](QUICK-PARTS-DIRECTION.md). First complete generic local import/update/remove → fast search → clearly typed preview → explicit copy in Client Communication and Document Language. Use fictional packs while real exports are unavailable. Checkpoint it, then add temporary block composition, unresolved-field guards and explicit final review/copy. Case-aware suggestions consume recorded states with visible reasons; they never choose a conclusion or communication.
3. Strengthen adapters from current platform evidence and controlled fixtures; technical uncertainty stays technical. Validate dynamic full-page capture before implementing nested scrolling. Evaluate custom folder roots separately with supported permission and revoked/disconnected-access recovery.
4. Defer broader workflow/QC packs, richer annotation, encrypted resume capsules and optional AI. None is necessary for the first excellent retrieval/composition workflow.

Pack content remains separate from cases and public source. An absent real corpus does not block generic engineering, but it cannot establish a real taxonomy or approval. Search and composition run offline after import. No passive collection, cloud case storage, name-based merging, automated identity/relationship conclusions, threat scoring or email sending. X stays search-only.
